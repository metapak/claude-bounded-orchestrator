# Local browser console

On macOS, double-click `launchers/Bounded Orchestrator.app`; on Windows, double-click `launchers/Launch Bounded Orchestrator.vbs`. Choose an existing project folder in the native picker. The browser opens a loopback-only setup screen where **Check changes** shows a preview and **Install** applies the first setup. These GUI launchers require Python 3.11+ and stay open until you choose **Close console** in the browser. Keep the installer repository/release folder for later updates. There is no global installation.

Alternatively, from this downloaded/cloned installer repository, run:

```sh
python3 scripts/configure.py /path/to/project
# Optional: keep the URL in the terminal; choose a fixed loopback port
python3 scripts/configure.py /path/to/project --no-browser --port 8765
```

Python 3.10+ is required; no npm, server account or Claude CLI is needed to open the UI. The browser opens by default. Use the full printed URL containing the private fragment token. Stop with Ctrl+C. The launcher lives in this repository/release archive, not in an installed target; retain the installer directory to configure later. Only an existing project directory is supported; user-wide installation is not supported by this installer.

**Preferences** shows the selected project's model/effort files, profiles, planned helper team and the supported concurrency environment setting. The conductor remains separate. You choose 1–10 stable helper slots, each with a duty, Claude model, effort and optional short label; duplicate duties are allowed. Saving creates real `.claude/agents/orchestra-slot-XX.md` definitions using the corresponding role's tool restrictions and adds routing names to the installer-managed `CLAUDE.md` block. The count is team capacity, not a requirement to spawn all helpers on each request; it differs from the concurrency preference and the observed helper count on the Usage page. Presets update slot model/effort only when explicitly selected. A previously saved team above 10 slots is shown read-only and is never silently truncated. Preview validates every role/slot and shows the exact selected fields and affected paths. Install/Save is the only operation that changes the project. On a fresh project, its preview explicitly includes initial toolkit installation via the existing installer. Conflicting existing agent files stop the operation for manual review. Existing managed files must still match installer-owned hashes. Shared settings retain unrelated keys, permissions and environment entries; their contents and credentials never enter API responses. Console-merged settings survive uninstall. Backups use the installer backup directory. Restore refuses files changed since Save and restores the immediately preceding console-managed configuration. After a first Save, Restore leaves the initial toolkit installed; use the documented installer uninstall to remove it. Restart Claude Code after changing settings.

Project/local/managed settings, process environment, model availability and session CLI overrides can change runtime behavior. The console shows project-file values rather than claiming to know the effective live session. Owner effort persists as low/medium/high/xhigh; child effort follows the existing native Claude validation. The concurrency control writes `env.CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (1–20 console range), requires Claude Code 2.1.217+, and is bypassed by ultracode; resuming agents and other runtime features can exceed it. The default policy uses one specialist. Soft preferences about brief reports, context and retries are instructions, never a hard token budget or subscription-quota estimate.

**Kullanım** reads only a local sanitized OTLP JSON/JSONL file whose path you explicitly enter. Telemetry is opt-in and this console never enables it. Only explicit Sum delta/cumulative metrics count. Export duplicates and repeated timestamped points are deduplicated; independent cumulative streams are ordered by timestamp, differenced and reset separately. Identical untimestamped delta points within one document cannot be reliably distinguished and count separately. Date filters use UTC observation dates, exclude undated points and keep pre-range cumulative baselines; increments can span filter boundaries. Model, date, session/thread and agent dimensions appear only when the export supplies them. Actual input/output/cacheRead/cacheCreation values retain OTLP names; missing counters and task attribution remain unavailable. Cost metrics, if supplied, are reported separately as source values with no price estimate. No conversion to subscription quota is made. Missing, malformed, unsupported or empty exports show an unavailable/error state. A 32 MiB file limit bounds local loading.

The model chart uses only `claude_code.token.usage` points and adds input plus output for its main total. Cache read and cache creation remain separate, so cached input is not counted a second time. Standard Claude Code OTLP does not identify a project or working profile; ordinary exports therefore show work style as unknown. The console keeps a private, gitignored record of its own Save/Restore profile changes, containing timestamps, a project-path hash, preset names and manifest digests only. A work style is *estimated from settings history* only when an export explicitly includes `project.path`, exactly one fresh `claude_code.session.count` start for that session, and every observed token point stays within one recorded profile interval. Missing/ambiguous sessions, unobserved earlier settings and changes outside the console remain unknown. Date filtering does not change this full-session attribution check. The sample chart is synthetic, not user usage.

The orchestra illustration shows observed token shares in a selected `session.id`, never context-window occupancy or quota remaining. Its helper count is observed history, separate from the concurrency preference. The official `query_source` attribute identifies `main`, `subagent`, and `auxiliary` requests; `agent.name` identifies a subagent *type*, not an individual. Thus the conductor is only the observed `main` aggregate, unlabelled subagent usage is one group with unknown headcount, and other sources remain unassigned. Individual helpers appear only if optional custom metric attributes consistently provide `orchestra.agent.id`, `orchestra.parent.id`, and `orchestra.root.id`, with an observed root. `orchestra.agent.name` and `orchestra.agent.role` may supply display text; they are not identity. These attributes are not emitted by standard Claude Code telemetry. Actor models come from observed token metrics, including a per-model breakdown when more than one appears. Effort is not present in standard OTLP metrics: when the observed role matches a saved project role, the UI displays its **currently configured** effort, which does not establish the effort used in that historical session. Unmatched roles and duplicate configured slots of the same role show unknown because the historical slot cannot be identified. The conductor stays still on initial load. Clicking it starts motion until the next click elsewhere, including under reduced motion because the user explicitly requested that motion. The sample orchestra uses synthetic explicit identities; it does not imply live agent tracking. [Anthropic's monitoring reference](https://code.claude.com/docs/en/monitoring-usage) defines the official fields.

**Görev Ayrıntıları** reads the selected project's metadata-only task ledger. It does not read session transcripts, invent tasks, or attribute tokens/cost to ledger tasks. No ledger means an explicit unavailable state.

The server binds only `127.0.0.1`, validates Host and Origin, requires a random header token for all API reads/writes and a same-origin JSON POST for mutations, limits request bodies and never runs shell text from a request. Assets use a restrictive content security policy. Treat the printed URL as private local access. API output does not contain full settings, environment values, API keys or transcript bodies.

Verified primary references (2026-09-29): [subagent frontmatter, context, concurrency and resume](https://code.claude.com/docs/en/sub-agents), [model and effort settings](https://code.claude.com/docs/en/model-config), [OTLP token/cost counters and dimensions](https://code.claude.com/docs/en/monitoring-usage). `omitClaudeMd: true` for the independent reviewer requires Claude Code 2.1.271+; its brief must repeat relevant policy and invariants. Older clients may load additional context. CLI was unavailable in local validation; file/API tests do not prove a live Claude session accepted every model or effort choice.
